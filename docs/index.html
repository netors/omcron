Theme

omcron

Repeating jobs for Omarchy. Each one either runs on schedule and tells you how it went, or posts a notification and waits for you to approve it.

Install

Two commands

omarchy plugin add https://github.com/netors/omcron.git --enable --yes
~/.config/omarchy/plugins/netors.omcron/install.sh

The first installs the bar widget. The second puts the omcron command on your PATH. Both are needed.

Put the widget where you want it on the bar:

omarchy bar put netors.omcron --section center --after omarchy.indicators

Without the bar widget

git clone https://github.com/netors/omcron.git && cd omcron && ./install.sh

Requirements

  • bash 4+, jq, and a systemd user instance
  • omarchy-notification-send and omarchy-menu-select for notifications and the approval picker
  • A Nerd Font for the bar glyphs

Updating

omarchy plugin update netors.omcron

This updates the command and the widget together.

Quick start

Three commands to see it work

# create a job that runs every day at midnight
omcron add hello --at daily --auto --desc 'Smoke test' --run echo hi

# run it now, without waiting
omcron run hello

# see what it did, then remove it
omcron log hello
omcron rm hello

Creating jobs

A name, a schedule, a command, and a mode

omcron add <name> --at <schedule> [--auto|--ask] [--persistent] [--desc "text"] --run <command...>
FlagMeaning
--atWhen it runs. See Schedules. Required.
--autoRun on schedule without asking.
--askPost a notification and wait for approval. This is the default.
--persistentIf the machine was off at the scheduled time, run at the next boot instead of skipping.
--descThe label shown in notifications and the bar tooltip. Defaults to the job name.
--runThe command, as separate words. Must come last.
--shellA shell command line instead, when you need pipes, globs or redirection.

--run and --shell

--run takes the command as separate words and consumes everything after it, so it has to be the last flag:

omcron add claude --at 'Mon..Fri 09:30' --ask --desc 'Upgrade Claude' \
  --run mise upgrade claude

Use --shell when you want the shell to interpret the line:

omcron add trash --at weekly --auto --persistent \
  --shell 'find ~/.local/share/Trash -mtime +30 -delete'

Schedules

systemd OnCalendar expressions, not cron syntax

WriteRuns
dailyEvery day at midnight
hourlyEvery hour, on the hour
weeklyMondays at midnight
Mon..Fri 09:30Weekdays at 09:30
Sat,Sun 11:00Weekends at 11:00
*:0/15Every 15 minutes
*-*-01 08:00The 1st of each month at 08:00
2026-12-25 09:00Once, at that moment
Checking one

Schedules are validated when you add the job, so a typo is rejected immediately. To test an expression yourself:

systemd-analyze calendar 'Mon..Fri 09:30'

Cron's */15 * * * * is not accepted. Write *:0/15.

Auto and ask

The one thing to decide per job

Runs on schedule, then tells you how it went.

A successful run posts a notification that clears itself. A failed run posts one that stays until you dismiss it, with the exit status. Clicking either opens the job's log.

Use it for backups, cleanups and syncs.

Posts a notification and runs nothing until you click it.

The notification stays on screen until you act on it, and remains clickable in notification history if you miss it. Clicking opens a menu with five choices.

Use it for upgrades, or anything you might want to decline while you are busy.

Change a job's mode later with omcron edit <name> --auto or --ask.

Approving a job

What happens when an ask job comes due

1

A notification appears

"Run: <description>?" It stays until you act on it. If you miss it, it is still in notification history and still clickable.

2

Click it

A menu opens with five options. You can also click the bar widget, which opens the menu for the oldest waiting job.

3

Choose

Only Run, Skip and Snooze answer the request. Reading the log or pressing Esc leaves it waiting, so nothing is lost by looking first.

Run now

Runs the command and reports the result.

Skip this one

Declines this run. The schedule is unchanged.

Snooze 15m / 1h

Asks again later. The schedule is unchanged.

Open the log

Opens past output. Still waiting afterwards.

Esc

Closes the menu. The request comes back.

Ignoring a request

If you never answer, the job does not run. The next scheduled time replaces the old request with a new one. There is no automatic fallback to running it.

To see what is waiting, or answer it from the terminal:

omcron pending
omcron answer

Bar widget

What it shows, and what clicking does

The widget shows a timer glyph when jobs are scheduled, and an alert glyph in the urgent colour when one is waiting for you. Hover it to list every job and when it next runs.

ClickDoes
With a job waitingOpens the approval menu for the oldest waiting job
With nothing waitingShows a summary of the schedule

Settings

Editable from the bar's own settings panel, or directly in ~/.config/omarchy/shell.json.

SettingDefaultDoes
showWhenEmptytrueStay on the bar, dimmed, when there are no jobs
attentionOnlyfalseHide unless a job is waiting. Overrides the setting above
refreshIntervalSec60How often it re-reads state. Changes you make with omcron show up immediately regardless

Commands

The full surface

CommandDoes
omcron add <name>Create a job
omcron listEvery job, its schedule, next run and command
omcron list --jsonThe same as JSON
omcron show <name>One job in full, including its log path
omcron run <name>Run it now, without asking
omcron test <name>Pretend it came due. An ask job really does ask
omcron log <name> [n]Output of past runs, most recent last
omcron pendingRequests waiting on you
omcron answerOpen the menu for the oldest waiting request
omcron statusPost a summary of the schedule as a notification
omcron edit <name>Change schedule, mode, description or persistence
omcron enable <name>Resume a paused job
omcron disable <name>Pause it without deleting it
omcron rm <name>Delete the job. Its log is kept
omcron doctor [--fix]Check the install and repair what it can
omcron versionPrint the version

Editing a job

omcron edit backup --at 'Sun 03:00'      # change when it runs
omcron edit backup --auto                # stop asking first
omcron edit backup --persistent          # catch up missed runs
omcron edit backup --desc 'Nightly backup'

To change the command itself, remove the job and add it again.

Files

Where everything lives

PathContains
~/.config/omcron/jobs/<name>.jsonThe job definition
~/.config/systemd/user/omcron-<name>.{service,timer}Generated systemd units. Do not edit by hand — omcron edit rewrites them
~/.local/state/omcron/<name>.logOutput of past runs, with timestamps and exit status
~/.config/omarchy/plugins/netors.omcron/The plugin: bar widget and the command itself
~/.local/bin/omcronSymlink to the command inside the plugin directory

Jobs run under systemd, so systemctl --user list-timers 'omcron-*' and journalctl --user -u omcron-<name>.service both work as usual.

Troubleshooting

Start here

omcron doctor

Checks that everything it needs is present, that each job's units exist and point at the right place, and that nothing has been left behind. omcron doctor --fix repairs what it can.

A job did not run

  • Is it enabled? omcron list shows disabled in the next-run column.
  • Was the machine asleep at the time? Without --persistent the run is skipped. Add it with omcron edit <name> --persistent.
  • Is it an ask job you did not answer? Check omcron pending.
  • Look at the log: omcron log <name>, and the unit's own output with journalctl --user -u omcron-<name>.service.

"command not found" inside a job

Jobs run with the PATH that was in effect when you created them, so a tool installed somewhere new afterwards will not be found. Remove the job and add it again from a shell where the command works:

omcron show <name>          # note the schedule and command
omcron rm <name>
omcron add <name> --at ... --run ...

omcron edit does not re-capture PATH.

The bar widget is missing or dimmed

  • Dimmed with a tooltip about install.sh means the plugin is installed but the command is not on your PATH. Run the second install step.
  • Absent entirely: check it is placed with omarchy bar put netors.omcron --section center.
  • Check attentionOnly is not hiding it, and that omcron list --json works from a terminal.

Notifications do not appear

Confirm the notifier exists: omcron doctor lists it under desktop integration. Approval requests are sent at critical urgency, so do-not-disturb does not suppress them.

Uninstall

# remove jobs first — this also removes their systemd units
omcron list
omcron rm <name>

# then the command and the widget
~/.config/omarchy/plugins/netors.omcron/install.sh --uninstall
omarchy plugin remove netors.omcron

Logs under ~/.local/state/omcron/ are left behind; delete them yourself if you want them gone.
